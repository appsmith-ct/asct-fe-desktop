# CLAUDE.md — asct-fe-desktop

This is the UI submodule of Appsmith-CT. It is normally checked out inside `asct-app/`, whose `docs/`
directory holds the authoritative implementation specification and the current milestone progress log
(`asct-app/docs/PROGRESS.md`). Read both before starting work here if they are reachable; this file only
covers conventions local to this repository.

## What this repo is

A React + TypeScript + Vite app, eventually wrapped by Tauri v2 (`src-tauri/`, added in M8). It is purely an
observer and controller of engine runs: it talks to `asct-be-engine` over REST for data and a WebSocket for
the live event stream, and never calls a model or touches the filesystem itself. Until M8 it runs as a
plain local web app in the browser — that's an accepted dev mode, not a shortcut to skip.

## Conventions

- **Commit without asking.** The user has given standing permission to commit at your own
  judgement. Commit when a coherent piece of work is finished and verified (`pnpm build`, `pnpm lint`,
  and `pnpm run e2e` where it's affected — all green), not mid-change, with an imperative subject and a short
  body explaining *why*, plus a `Co-Authored-By` trailer. Straight to `main`, matching this
  repo's existing linear history. After committing here, remember the **root repo's submodule
  pointer** needs its own commit in `asct-app` — a submodule commit alone leaves the root
  pointing at the old revision. Pushing is still a separate decision: ask before `git push`.
- `pnpm`, not `npm`/`yarn`.
- The engine is the source of truth for API shape: its OpenAPI document and event schema are exported to
  `asct-app/docs/api/`, and this repo's TypeScript client (`pnpm run gen-api`, `src/api/generated/`) is
  generated from that, not hand-written against guessed shapes. The two WebSocket routes aren't in the
  OpenAPI document (it's REST-only) — their message shapes are hand-synced instead
  (`src/api/useChatSocket.ts`, `src/api/useRunEvents.ts`), matching `appsmith.core.events.Event` and
  `appsmith.api.routers.chat`'s frame shape on the engine side.
- `openapi-typescript` cannot run as a local devDependency in this repo — it uses a `ts.factory` API this
  project's `typescript` (currently the 7.x Go-rewrite preview) doesn't have, failing with
  `Cannot read properties of undefined (reading 'createKeywordTypeNode')`. `pnpm run gen-api` instead
  shells out via `pnpm dlx openapi-typescript@7`, which resolves its own compatible `typescript` in an
  isolated environment. Don't move it back to a regular devDependency without confirming TS5-vs-TS7
  compatibility has actually changed.
- `pnpm lint` (oxlint) and `pnpm build` (`tsc -b && vite build`) must both pass before a change is done.
- Tailwind v4 (`@tailwindcss/vite`) for styling, `@xyflow/react` for the Pipeline screen's graph.
  `src/components/ui/` is a hand-built shadcn-style component set (button, badge, card, input, textarea,
  label, separator, switch, table, tabs, dialog, select), not generated by the `shadcn` CLI — that CLI
  currently errors ("Could not load the workspace config") against this repo's split
  `tsconfig.json`/`tsconfig.app.json` layout, on both its current release and the earlier version it
  suggests as a fallback. Copying the known Radix+Tailwind source directly is shadcn's own distribution
  model anyway (components are meant to be copied into the repo, not installed as a package) — add new
  components the same way rather than fighting the CLI, unless a future CLI release fixes this.
- A React component that needs the *current route's* params but isn't rendered inside the matched
  `<Route>` (e.g. `App.tsx`'s `Sidebar`, a sibling of `<Routes>`) must use `useMatch('/pattern/:id/*')`
  from `react-router`, not `useParams()` — `useParams()` only sees params from routes it's nested under,
  and silently returns an empty object otherwise rather than erroring. Found when the sidebar's
  project-scoped nav links never appeared.
- Vite's dev server binds to the IPv6 loopback under the `localhost` hostname by default on Windows, not
  the IPv4 literal — hitting it via `http://127.0.0.1:<port>` connection-refuses even though the server is
  genuinely listening on that port (confirm with `netstat -an`, not just `curl`, if a "why won't this
  connect" mystery comes up). Local tooling here (`scripts/screenshot.mjs`, `playwright.config.ts`) targets
  `localhost`, not `127.0.0.1`, for this reason — the engine itself binds the IPv4 literal explicitly via
  uvicorn's own `host` argument, so it doesn't have this issue.
- The screenshot pipeline (`scripts/screenshot.mjs`, `scripts/interact-and-shot.mjs`, both using
  Playwright's bundled Chromium — `pnpm exec playwright install chromium` once) is for the ongoing dev
  loop, not a one-off from M6: after a UI change, screenshot the affected screen and look at it, the same
  way you'd eyeball it in a real browser. It already caught several real bugs (see M6's plan doc) that
  `pnpm build`/`pnpm lint` passing cleanly did not.
- `<ReactFlow fitView>` fits **once, at mount**, and never again. Anything that appears around the
  canvas afterwards (the milestone gate banner above it, the Milestones panel beside it) shrinks the
  pane without a re-fit, leaving the nodes correctly rendered but scrolled out of view — a blank
  dotted canvas that only comes back on a page reload. `Pipeline.tsx` re-fits from a `ResizeObserver`
  on the pane element, deferred one `requestAnimationFrame`. Observe the pane rather than listing the
  state changes that can resize it: an effect keyed on `atMilestoneGate` was tried first and fires
  *before* the browser lays the new size out, so it re-fits to the size it's trying to replace.
  Found by screenshotting the gate state; `pnpm build` and `pnpm lint` were both perfectly happy.
- Playwright's `getByText('some text')` is a **case-insensitive substring** match. In `e2e/`, assert
  on a distinctive full sentence, or pass `{ exact: true }` — the milestone gate's "milestone demo"
  badge also matches the React Flow node labelled "Milestone demo", which made an assertion pass
  instantly against the wrong element and the next one fail for no visible reason.

## Build order

This repo is built milestone by milestone against the spec's section 10. M6 built the full REST/WebSocket
API and all seven screens (Projects, Chat, Pipeline, Artifacts, Workspace, Runs and metrics, Settings).
M7 added the milestone loop's UI: the Pipeline screen's Milestones panel (`MilestoneRail`), the milestone
demo pause with its change-request control (`MilestoneGate`), stale markers on the Artifacts screen, and a
version picker that actually loads the chosen version (the engine's artifact endpoint gained a `version`
query parameter — before M7 nothing ever had a v2, so the picker had been quietly inert). M8 (Tauri shell,
Model Manager) is not built yet — don't jump ahead without a concrete reason tied to that milestone's own
work.
